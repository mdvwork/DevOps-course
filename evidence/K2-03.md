# K2-03 — Compose и сохранение данных

## Цель

Запустить сервисы api и web из собственного образа `devops-student:v1` и проверить сохранность заявок после пересоздания API.

## 1. Конфигурация Compose

Создан `compose.student.yaml` на основе `compose.yaml`. Для сервисов `api` и `web` образ `devops-course:base` заменён на `devops-student:v1`. Другие настройки не изменялись.

Проверка конфигурации:

```bash
docker compose -f compose.student.yaml config -q
```

Команда завершилась без ошибок.

Основной стенд остановлен командой `docker compose stop`. Затем запущен стенд из `compose.student.yaml`.

Оба сервиса работали, API получил статус `healthy`, Web также прошёл проверку здоровья.

## 2. Доступность и сеть

Команда `curl -i http://127.0.0.1:8080/` вернула `HTTP/1.0 200 OK`.

Web опубликован на `127.0.0.1:8080`, который перенаправляет запросы на порт `8000` контейнера Web.

Web обращается к API по адресу `http://api:8000`. Имя `api` доступно во внутренней сети Compose. Между контейнерами используется порт API `8000`; публиковать его на хосте не требуется.

В Compose именованный том `requests` подключён к `/data` контейнера API. SQLite хранит заявки в `/data/requests.sqlite`.

## 3. Проверка до пересоздания API

Создана заявка с ключом `K2-03-before-recreate-20261022`.

Ответ содержал:

- ID заявки: `3`
- Тип: `screen`
- Экземпляр API: `dec37d4d2ac3`

До пересоздания список содержал заявки с ID 1, 2 и 3; всего 3 заявки.

## 4. Пересоздание API

Выполнена команда:

```bash
docker compose -f compose.student.yaml up -d --no-deps --force-recreate api
```

API снова получил статус `healthy`. Web продолжил работать.

После пересоздания список заявок по-прежнему содержал заявку № 3 и всего 3 заявки. Идентификатор экземпляра API изменился с `dec37d4d2ac3` на `7749e036f848`.

Повторная отправка того же ключа `K2-03-before-recreate-20261022` вернула заявку с ID 3, а не создала дубликат.

## 5. Проверка после пересоздания

Создана новая заявка с ключом `K2-03-after-recreate-20261022`.

Ответ:

- ID заявки: `4`
- Тип: `battery`
- Экземпляр API в этом ответе: `df93472e6aab`

Повторная проверка списка показала четыре заявки с ID 1, 2, 3 и 4.

## 6. Выводы

1. Сервисы `api` и `web` используют собственный образ `devops-student:v1`.
2. Web доступен на порту 8080 хоста, а API обслуживает запросы на внутреннем порту 8000.
3. Заявки сохраняются в SQLite-файле на именованном томе `requests`.
4. Заявка № 3 сохранилась после пересоздания API; новая заявка получила ID 4.
5. Хранить базу только в изменяемом слое контейнера ненадёжно: при удалении контейнера этот слой может быть потерян. Именованный том отделяет постоянные данные от жизненного цикла контейнера.

## Запуск стенда

Из корня репозитория:

```bash
docker compose -f compose.student.yaml config -q
docker compose -f compose.student.yaml up -d
docker compose -f compose.student.yaml ps
```

Остановка стенда:
bash
docker compose -f compose.student.yaml stop

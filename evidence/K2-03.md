# K2-03. Compose и сохранность данных

- Группа и код студента: 
- Команды: `docker compose stop`, `docker compose -f compose.student.yaml config --quiet`, `docker compose -f compose.student.yaml up -d`, POST `http://127.0.0.1:8080/api/requests`, `docker compose -f compose.student.yaml up -d --no-deps --force-recreate api`, GET `/api/requests`, ещё один POST `/api/requests`.
- Наблюдения: `api` и `web` запущены из `devops-student:v1` и имеют состояние `healthy`. Первая заявка в этой работе — №2 (`battery`). До пересоздания API ответ выдал экземпляр `43e56e0eb73e`, после — `64fe8d255a83`; список сохранил заявку №2 и ранее созданную №1. После пересоздания создана заявка №3 (`software`).
- Объяснение: `API_URL=http://api:8000` направляет обращения `web` к сервису `api` по имени внутри сети Compose и внутреннему порту 8000. Браузер обращается к `web` через `127.0.0.1:8080`, опубликованный на внутренний 8000. Том `requests:/data` хранит SQLite-файл отдельно от контейнера API, поэтому заявка №2 пережила пересоздание.
- Запуск из корня проекта: `docker build -f lab/Dockerfile -t devops-student:v1 lab`; `docker compose -f compose.student.yaml config`; `docker compose -f compose.student.yaml up -d`; открыть `http://localhost:8080`.
- Ответ на вопрос: при пересоздании изменяемый слой контейнера заменяется; без тома база в `/data` была бы потеряна.

# K2-05 — Диагностика взаимодействия Web и API

## Цель

Проверить взаимодействие контейнеров Web и API, воспроизвести ошибку из-за неправильного порта, изучить логи и восстановить работоспособность приложения.

## 1. Исходная конфигурация

В файле `compose.student.yaml` использовалась настройка:

    API_URL: http://api:8000

Web опубликован на хосте как `127.0.0.1:8080->8000/tcp`. API доступен внутри сети Compose на порту `8000`.

## 2. Воспроизведение ошибки

Временно изменён адрес API на `http://api:9999`. После запуска командой `docker compose -f compose.student.yaml up -d web` контейнеры запустились, API имел статус `healthy`.

Запрос `curl -sS -i http://127.0.0.1:8080/api/requests` вернул:

    HTTP/1.0 503 Service Unavailable
    {"error": "upstream_unavailable", "request_id": "7b8456af"}

В логах Web зафиксированы следующие сведения:

- Событие: `upstream_unavailable`.
- ID запроса: `7b8456af`.
- Целевой адрес: `http://api:9999`.
- Ошибка: `Connection refused` (соединение отклонено).

Web не смог подключиться к API по неправильному порту. При этом проверки `/health` самого Web продолжали возвращать HTTP 200.

## 3. Исправление конфигурации

Восстановлена исходная настройка `API_URL: http://api:8000`. Команда `docker compose -f compose.student.yaml config -q` завершилась без ошибок.

После выполнения `docker compose -f compose.student.yaml up -d web` повторный запрос к `http://127.0.0.1:8080/api/requests` вернул `HTTP/1.0 200 OK`.

Ответ содержал четыре сохранённых запроса с ID 4, 3, 2 и 1. Значение `total` равно 4.

## 4. Выводы

1. При неправильном адресе API Web возвращает `503 Service Unavailable` для проксируемого запроса.
2. Логи Web указывают адрес недоступного сервиса и причину ошибки `Connection refused`.
3. Восстановление адреса `http://api:8000` вернуло успешное взаимодействие.
4. Для связи контейнеров используется внутренний порт API `8000`, а не опубликованный порт Web `8080`.
5. Адрес `127.0.0.1:8080` используется клиентом на хосте для доступа к Web. Внутри Compose сервисы обращаются друг к другу по имени сервиса и внутреннему порту.
6. После исправления конфигурации все четыре ранее созданных запроса остались доступны.

## Команды проверки

    docker compose -f compose.student.yaml config -q
    docker compose -f compose.student.yaml up -d web
    docker compose -f compose.student.yaml ps
    curl -sS -i http://127.0.0.1:8080/api/requests
    docker compose -f compose.student.yaml logs --tail=30 web

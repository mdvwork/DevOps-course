# K2-04 — Локальный Docker Registry

## Цель

Запустить локальный Registry, отправить в него собственный образ, загрузить образ обратно и проверить совпадение digest.

## 1. Запуск Registry

Выполнена команда:

```bash
docker compose -f compose.student.yaml --profile registry up -d registry
```

Контейнер `devops-course-registry-1` успешно запущен. Порт Registry опубликован как `127.0.0.1:5000->5000/tcp`. Для хранения данных создан именованный том `devops-course_registry`.

## 2. Подготовка тега

Образу добавлен тег для локального Registry:

```bash
docker tag devops-student:v1 localhost:5000/workshop:v1
```

Проверка показала, что оба тега указывают на один Image ID:

`sha256:8b93bcb49e9d8b570da15469534b9331b43fc2c598c2981f7fec993032ae822b`

## 3. Отправка образа

Выполнена команда:

```bash
docker push localhost:5000/workshop:v1
```

Результат: все девять слоёв получили статус `Pushed`.

Digest из вывода команды:

`sha256:8b93bcb49e9d8b570da15469534b9331b43fc2c598c2981f7fec993032ae822b`

Размер манифеста: 856 байт.

## 4. Загрузка образа

Выполнена команда:

```bash
docker pull localhost:5000/workshop:v1
```

Registry вернул тот же digest:

`sha256:8b93bcb49e9d8b570da15469534b9331b43fc2c598c2981f7fec993032ae822b`

Статус: `Image is up to date for localhost:5000/workshop:v1`.

## 5. Проверка метаданных

Выполнена команда:

```bash
docker image inspect localhost:5000/workshop:v1
```

Результаты:
- Image ID: `sha256:8b93bcb49e9d8b570da15469534b9331b43fc2c598c2981f7fec993032ae822b`
- Теги: `devops-student:v1`, `localhost:5000/workshop:v1`
- Размер образа: 192660635 байт
- Пользователь: `10001:10001`
- Метка `course.student`: `student-A`

В `RepoDigests` присутствует digest репозитория `localhost:5000/workshop` с тем же значением.

## 6. Выводы

1. Локальный Registry доступен по адресу `localhost:5000`.
2. Образ `localhost:5000/workshop:v1` успешно отправлен и загружен обратно.
3. Digest после `push` совпал с digest после `pull`, что подтверждает совпадение идентификатора содержимого образа.
4. `docker push` только публикует образ в Registry и не запускает приложение. Для запуска контейнера используется `docker run`, а для запуска Compose-сервисов — `docker compose up`.
5. Для этого локального учебного Registry отдельная учётная запись не потребовалась.

## Команды для повторения

```bash
docker compose -f compose.student.yaml --profile registry up -d registry
docker tag devops-student:v1 localhost:5000/workshop:v1
docker push localhost:5000/workshop:v1
docker pull localhost:5000/workshop:v1
docker image inspect localhost:5000/workshop:v1
```

# K2-02. Свой Dockerfile

- Группа и код студента:
 метка `course.student` пока пустая по просьбе студента.
- Команды: `docker build -f lab/Dockerfile -t devops-student:v1 lab`, `docker image inspect devops-student:v1 --format '{{json .Config.Labels}}'`, `docker run --rm -d --name student-web -p 127.0.0.1:8081:8000 -e ROLE=web devops-student:v1`, HTTP GET `http://127.0.0.1:8081/health`, `docker logs student-web`, `docker stop student-web`.
- Наблюдения: сборка завершилась успешно; inspect вернул `{"course.student":""}`. Контейнер запустился; ответ `/health`: `{"process":"running","role":"web"}`. В логах: `event=started`, `port=8000`, запрос `GET /health` со статусом 200. После проверки контейнер остановлен.
- Объяснение: `FROM` задаёт Python-основу; `WORKDIR` — `/app`; `ENV` включает вывод без буферизации; `COPY` переносит `app.py` и `index.html` из контекста `lab`; `RUN` при сборке создаёт `/data` с правами UID/GID 10001; `USER` запускает приложение от этого пользователя; `LABEL` хранит метку; `CMD` запускает Python при старте контейнера.
- Ответ на вопрос: `EXPOSE 8000` лишь описывает порт внутри образа; доступ с компьютера обеспечил параметр `-p 127.0.0.1:8081:8000`.
- До сдачи: заполнить метку своим кодом, пересобрать образ и повторить `inspect`. Отдельный запуск только `web` не проверяет приём заявок.

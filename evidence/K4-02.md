
# K4-02. Prometheus и Grafana

## 1. Запуск мониторинга

Команда:

```bash
docker compose -f compose.student.yaml --profile monitoring up -d
docker compose -f compose.student.yaml --profile monitoring ps
```

Результат:
- API запущен и имеет статус healthy.
- Web запущен и имеет статус healthy.
- Prometheus запущен на порту 9090.
- Grafana запущена на порту 3000.

## 2. Конфигурация Prometheus

Файл `monitoring/prometheus.yml` содержит:
- интервал сбора метрик — 5 секунд;
- задание `workshop`;
- цели сбора метрик `api:8000` и `web:8000`.

В Prometheus на странице `/targets` обе цели отображались со статусом UP.

Запрос:

```promql
up{job="workshop"}
```

Результат: две временные серии со значением 1 — для API и Web.

## 3. Проверка HTTP-метрик

В Grafana выбран источник данных `Workshop Prometheus`.

Первый запрос:

```promql
devops_http_requests_total{role="web",status="200"}
```

Запрос отображает количество успешных HTTP-запросов Web.

Второй запрос:

```promql
rate(devops_http_requests_total{role="web",status="200"}[1m])
```

Запрос рассчитывает скорость успешных HTTP-запросов Web за последнюю минуту.

Во время проверки значение rate оставалось равным 0. Ненулевое значение получить не удалось, поэтому это наблюдение не считается подтверждением роста скорости запросов.

## 4. Dashboard Grafana

Создана панель со следующими настройками:
- название: `Успешные HTTP-запросы Web`;
- визуализация: Time series;
- источник данных: `Workshop Prometheus`;
- запрос: `rate(devops_http_requests_total{role="web",status="200"}[1m])`;
- единицы измерения: requests/sec.

Dashboard экспортирован в файл:

`evidence/K4-02-dashboard.json`

Проверка JSON подтвердила:
- тип объекта Dashboard;
- формат Dashboard API v2;
- наличие элемента `panel-1`;
- правильность названия панели;
- наличие Prometheus-запроса;
- единицы измерения `reqps`.

## 5. Проверка понимания

Счётчик `devops_http_requests_total` может сброситься при перезапуске процесса или контейнера, поскольку счётчик хранится в памяти процесса.

При этом сами заявки могут оставаться сохранёнными, если приложение записывает их в постоянное хранилище, например Docker volume.

Таким образом, метрики процесса и сохранённые данные приложения имеют разный жизненный цикл.

## 6. Вывод

Prometheus и Grafana успешно запущены.

Prometheus собирает метрики API и Web, обе цели имеют статус UP.

В Grafana создана панель мониторинга успешных HTTP-запросов Web и экспортирована в JSON.

Запросы PromQL настроены. Значение rate во время проверки оставалось равным 0, что зафиксировано в отчёте.

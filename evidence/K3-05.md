# K3-05 — Разбор ошибки Docker build в CI

## Цель

Проверить, как GitHub Actions сообщает об ошибке при отсутствии Dockerfile, найти первую полезную строку ошибки, объяснить причину, исправить путь и повторно запустить pipeline.

## Эксперимент

В файле `.github/workflows/student-ci.yml` временно изменён аргумент `-f` команды сборки:

```bash
docker build -f lab/MissingDockerfile -t devops-student:${{ github.sha }} lab
```

### Наблюдение

Коммит с намеренно неправильным путём: `70fed53`.

В логе шага сборки получено сообщение:

```text
ERROR: failed to build: failed to solve: failed to read dockerfile: open MissingDockerfile: no such file or directory
Error: Process completed with exit code 1.
```

Ссылка на запуски CI: https://github.com/Andrew22810/DevOps-course/actions

### Диагноз

Docker не смог прочитать файл `lab/MissingDockerfile`, поскольку такого файла нет в каталоге `lab`. Без Dockerfile Docker не может получить инструкции для сборки образа, поэтому задача `build` завершилась с кодом `1`.

Это ошибка конфигурации сборки, а не ошибка тестов приложения. Тесты проверяют поведение приложения; в этом эксперименте причина сбоя возникла на этапе чтения Dockerfile.

## Исправление

В коммите `2d439b0` путь восстановлен:

```bash
docker build -f lab/Dockerfile -t devops-student:${{ github.sha }} lab
```

После исправления GitHub Actions завершился успешно:

- `test` — Success;
- `build` — Success.

## Вывод

Эксперимент подтвердил, что неверный путь к Dockerfile приводит к ошибке сборки.
Первая полезная часть сообщения — `failed to read dockerfile` и `no such file or directory` — 
указывает на отсутствие файла по заданному пути. После восстановления `lab/Dockerfile` обе задачи pipeline 
успешно завершились

# K3-04 — Docker build job with test dependency

## Цель

Добавить отдельную задачу `build` в GitHub Actions, которая собирает Docker-образ только после успешного завершения задачи `test`.

## Реализация

В `.github/workflows/student-ci.yml` добавлена задача:

```yaml
build:
  runs-on: ubuntu-latest
  needs: test
  steps:
    - uses: actions/checkout@d23441a48e516b6c34aea4fa41551a30e30af803 # v6
      with:
        persist-credentials: false
    - run: docker build -f lab/Dockerfile -t devops-student:${{ github.sha }} lab
```

Образ собирается из `lab/Dockerfile` и получает тег с SHA текущего коммита. Зависимость `needs: test` не позволяет выполнять сборку при провале тестов.

## Проверка

1. **Успешный тест и сборка:** коммит `d3e2016` — добавлена задача `build`; обе задачи завершились успешно.
2. **Провал теста:** коммит `379e64f` — ожидаемый HTTP-статус временно изменён с `201` на `200`. Задача `test` завершилась с ошибкой, а `build` была пропущена (`Skipped`).
3. **Восстановление теста:** коммит `5954614` — ожидаемый статус возвращён к `201`; обе задачи `test` и `build` завершились успешно.

Запуски CI доступны во вкладке Actions репозитория: https://github.com/Andrew22810/DevOps-course/actions

## Вывод

Задача `build` отделена от `test` и зависит от неё через `needs: test`. Эксперимент подтвердил, что при провале тестов Docker-сборка пропускается. После восстановления теста обе задачи проходят успешно.

# K2-01 — Образ Docker

# 1. Проверка образа Docker

Команда:

`docker image inspect devops-course:base`

Обнаруженные свойства:

- Тег образа: `devops-course:base`
- ID образа: `sha256:3df912c91182cad60e59905ce02d5ad815b1234e2c3ee710ac0271724ef581bb`
- Базовый образ: `python:3.13-slim-bookworm`
- Рабочая директория: `/app`
- Команда запуска: `python app.py`
- Пользователь: `10001:10001`
- Объявленный порт контейнера: `8000/tcp`
- Операционная система: Linux
- Архитектура: amd64

# 2. Сервисы Docker Compose

Команды:

- `docker compose config`
- `docker compose up -d`
- `docker compose ps`

Оба сервиса запустились и получили статус `healthy`.

- `api` использует образ `devops-course:base` с переменной окружения `ROLE=api`. Данные приложения хранятся в `/data`, который связан с именованным томом `devops-course_requests`.
- `web` использует тот же образ с переменной окружения `ROLE=web`. Порт контейнера `8000` опубликован на адресе компьютера `127.0.0.1:8080`.
- Сервис `web` зависит от готовности сервиса `api`: перед запуском `web` сервис `api` должен иметь статус `healthy`.

# 3. Первоначальная проверка HTTP-запросов

Команды:

- `curl -i --max-time 5 http://127.0.0.1:8080/`
- `curl -i --max-time 5 http://127.0.0.1:8080/health`

Результаты:

- Главная страница вернула ответ `HTTP/1.0 200 OK`.
- Эндпоинт проверки состояния вернул ответ `HTTP/1.0 200 OK`.
- Ответ проверки состояния: `{"process": "running", "role": "web"}`.

Затем была отправлена тестовая заявка на адрес `/api/requests` с типом `screen` и ключом `K2-01-test-20261017-01`.

Результат: `HTTP/1.0 201 Created`, идентификатор заявки — `1`.

Последующий GET-запрос к `/api/requests` вернул `total: 1`, что подтвердило наличие одной заявки.

# 4. Остановка только сервиса web

Команды:

- `docker compose stop web`
- `docker compose ps`
- `curl -i --max-time 5 http://127.0.0.1:8080/`

Результаты:

- Контейнер `web` остановился.
- Контейнер `api` продолжил работать и сохранил статус `healthy`.
- HTTP-запрос к порту `8080` завершился ошибкой: `curl: (7) Failed to connect to 127.0.0.1 port 8080`.

Это подтвердило, что после остановки `web` главная страница стала недоступна, хотя сервис `api` продолжил работать.

# 5. Сохранение образа и повторный запуск web

Команда:

`docker image inspect -f 'Image ID: {{.Id}} | Tags: {{.RepoTags}}' devops-course:base`

Полученный результат:

`Image ID: sha256:3df912c91182cad60e59905ce02d5ad815b1234e2c3ee710ac0271724ef581bb | Tags: [devops-course:base]`

Образ остался доступен после остановки контейнера `web`.

Команды:

- `docker compose start web`
- `docker compose ps`
- `curl -i --max-time 5 http://127.0.0.1:8080/health`

Результаты:

- Оба сервиса снова работали со статусом `healthy`.
- Эндпоинт проверки состояния вернул `HTTP/1.0 200 OK`.

После перезапуска была отправлена вторая тестовая заявка на адрес `/api/requests` с типом `battery` и ключом `K2-01-test-20261017-02`.

Результат: `HTTP/1.0 201 Created`, идентификатор заявки — `2`.

# 6. Вывод

Образ Docker — это шаблон, на основе которого создаются контейнеры. Остановка контейнера не удаляет образ, из которого он был создан.

Остановка только `web` сделала веб-приложение недоступным, в то время как `api` продолжил работать. Повторный запуск `web` восстановил доступ к приложению без необходимости заново собирать образ.

Оба сервиса используют один и тот же образ, но работают с разными значениями переменной окружения `ROLE`.

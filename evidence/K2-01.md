# K2-01. Образ и контейнер

- Группа и код студента: 
- Подготовка: исходного образа на ПК не было; собран из `docker/bootstrap.Dockerfile` командой `docker build -f docker/bootstrap.Dockerfile -t devops-course:base lab`.
- Команды: `docker image inspect devops-course:base`, `docker compose up -d`, `docker compose ps`, `docker compose stop web`, `docker compose ps`, `docker compose start web`. Доступность проверена HTTP-запросами к `http://127.0.0.1:8080/health`; заявка отправлена POST-запросом к `/api/requests`.
- Наблюдения: образ имеет `USER 10001:10001`, `EXPOSE 8000/tcp`, `CMD ["python","app.py"]`. `api` и `web` запустились из одного `devops-course:base`: первый имеет `ROLE=api`, второй — `ROLE=web`. После остановки `web` сервис `api` остался `healthy`, но запрос к опубликованному порту 8080 завершился тайм-аутом. После запуска `web` ответ `/health` — `{"process":"running","role":"web"}`; POST создал заявку №1 (`kind=screen`).
- Вывод: образ — основа для разных контейнеров; остановка `web` убирает точку входа с компьютера, не удаляя образ или `api`. После возобновления связи заявки снова принимаются.
- Ответ на вопрос: остановка контейнера `web` не удаляет образ.

# K3-03 — Тестовый барьер

## Цель

Добавить автоматический запуск тестов приложения в Student CI и проверить, что неверное ожидание теста приводит к провалу CI, а исправление восстанавливает успешный запуск.

## Конфигурация

- Workflow: `.github/workflows/student-ci.yml`
- Runner: `ubuntu-latest`
- Python: `3.13`
- Команда: `python -m unittest discover -s tests -p test_app.py -v`
- Количество тестов: 7
- Проверяемый контракт: создание заявки возвращает HTTP `201 Created`.

## Эксперимент

### 1. Успешный запуск

- Коммит: `d14db1a` — `Run application tests with unittest discovery`
- Результат: `Success`
- Ссылка: https://github.com/Andrew22810/DevOps-course/actions/runs/39780271921

### 2. Намеренно ошибочное ожидание

- Коммит: `50f1d49` — `Test CI failure with incorrect status expectation`
- Изменение: ожидаемый статус `201` временно заменён на `200`.
- Результат: `Failure`.
- Существенные строки лога:
  - `test_create_request ... FAIL`
  - `AssertionError: 201 != 200`
  - `Ran 7 tests in 1.055s`
  - `FAILED (failures=1)`
  - `Process completed with exit code 1.`

Ошибка возникла потому, что приложение правильно вернуло HTTP `201`, а тест ожидал `200`. Неверное ожидание также является провалом теста, поэтому CI не должен считать проверку успешной.

Ссылка на запуск: https://github.com/Andrew22810/DevOps-course/actions/runs/39779733847

### 3. Восстановление правильного ожидания

- Коммит: `a894b26` — `Restore correct request status expectation`
- Исправление: восстановлено ожидание `201`.
- Локальная проверка: все 7 тестов прошли (`OK`).
- Запуск GitHub Actions: https://github.com/Andrew22810/DevOps-course/actions/runs/39780760788

## Вывод

Тестовый барьер проверен: правильное ожидание даёт успешный результат, намеренно неверное ожидание приводит к провалу CI, а восстановление `201` позволяет тестам пройти локально. CI использует exit code тестовой команды для определения результата шага.

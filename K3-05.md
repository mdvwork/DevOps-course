# K3-05. Разбор лога pipeline

Тесты в этом эксперименте не менялись. В команде сборки путь временно был `-f lab/MissingDockerfile`. Итоговый workflow снова указывает `-f lab/Dockerfile`. `continue-on-error` не добавлялся.

## Ошибочный запуск

`test` зелёный, `build` красный: тесты не открывают Dockerfile, а `docker build` открывает.

- Ссылка: https://github.com/desperact1vess/DevOps-course/actions/runs/46083112757
- Событие: push
- SHA: 8073be3
- Первая содержательная строка об отсутствующем файле: ERROR: failed to build: failed to solve: failed to read dockerfile: open MissingDockerfile: no such file or directory

Диагноз: флаг `-f` задаёт путь к Dockerfile относительно репозитория. Файла `lab/MissingDockerfile` в дереве коммита нет, поэтому демон Docker не начинает разбирать инструкции сборки. Это не ошибка слоёв `RUN` и не ошибка теста. Типичная формулировка в логе похожа на отказ открыть файл (`no such file or directory` или `failed to read dockerfile`). В отчёт переносится первая такая строка из своего журнала, а не пример из этого абзаца, если формулировка отличается.

## Исправленный запуск

Путь возвращён на `lab/Dockerfile`. Новый run: `test` и `build` зелёные.

- Ссылка: https://github.com/desperact1vess/DevOps-course/actions/runs/46083371774
- Событие: push
- SHA: b56510c

Зелёный `build` подтверждает, что файл по указанному пути снова находится и инструкции в нём выполнились до конца.

## Проверка понимания

Отсутствие Dockerfile отличается от ошибки теста местом и смыслом. Ошибка теста останавливает job `test`: контракт HTTP не сошёлся, до сборки очередь не доходит, `build` будет skipped. Отсутствие Dockerfile при живом тесте означает, что приложение для unittest запустилось из `lab/app.py`, а сборка образа не нашла свой входной файл. Красным становится job `build`, job `test` при этом зелёный.

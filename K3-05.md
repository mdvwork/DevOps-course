# K3-05. Разбор лога pipeline

В ветке на один коммит команда сборки смотрит на `-f lab/MissingDockerfile`. Тесты и `continue-on-error` не трогаются. В файле, который остаётся после работы, путь снова `lab/Dockerfile`.

## Запуск со сломанным путём

Ожидаемая картина: job `test` successful, job `build` failed. Unittest запускает `lab/app.py` как скрипт и про Dockerfile не знает.

- URL: https://github.com/anstep817/DevOps-course/actions/runs/46072468079
- Событие: push
- SHA: 42b1dea
- Первая содержательная строка лога: ERROR: failed to build: failed to solve: failed to read dockerfile: open MissingDockerfile: no such file or directory

Диагноз по этой строке: Docker получил явное имя файла инструкции и не смог его прочитать, потому что такого пути в checkout нет. Слои образа не строились. Если в своём логе формулировка другая, в отчёт копируется она, начиная с первого упоминания отсутствующего файла, а не общая фраза «сборка упала».

## Запуск после возврата пути

- URL: https://github.com/anstep817/DevOps-course/actions/runs/46072697222
- Событие: push
- SHA: ce6cd81

Повторный `docker build -f lab/Dockerfile` доходит до конца, оба job зелёные. Старый run с `MissingDockerfile` остаётся красным: он привязан к прежнему SHA.

## Проверка понимания

Это не та же красная сборка, что при падении теста. Когда ошибочен тест, `build` не стартует и в его логе пусто, статус skipped. Когда нет Dockerfile, тест уже прошёл, а сборка стартовала и упала на чтении файла. По статусам двух job видно, на каком барьере остановился pipeline.

# K3-02. Первый workflow

Workflow лежит в `.github/workflows/student-ci.yml` и называется `Student CI`. События в файле — `push` и `pull\_request`. Ниже фиксируется тот run, который открыт руками, и его фактическое событие.

## Свой запуск

* URL run: https://github.com/anstep817/DevOps-course/actions/runs/46066741403
* Событие: push
* SHA run: 2d76a5d
* Runner job `test`: `ubuntu-latest`

Если кнопка Actions недоступна, вместо ссылки пишется, что именно показал GitHub (запрет Actions у организации, приватный форк без минут и так далее). Файл при этом уже должен быть в ветке.

## Роль job и шагов

Job `test` ограничен пятью минутами и идёт на `ubuntu-latest`. Пока шаг не упал, следующий шаг того же job видит файлы, которые предыдущий положил на диск.

* Checkout забирает дерево коммита. Используется тот же SHA action, что в шаблоне курса: `actions/checkout@d23441a48e516b6c34aea4fa41551a30e30af803`. Учётные данные для push не сохраняются.
* Setup Python включает CPython 3.13 тем же action, что в шаблоне: `actions/setup-python@ece7cb06caefa5fff74198d8649806c4678c61a1`.

Команда `python --version` нужна как проверка, что интерпретатор реально вызвался. Строка из лога: Python 3.13.18
Без checkout рабочий каталог runner пустой, и тесты из следующих пунктов нечего запускать. Без setup-python на образе runner может не быть нужной версии, даже если команда `python` случайно найдётся.

## Проверка понимания

Успешная печать версии не означает, что приложение отвечает. Шаг не импортирует `lab/app.py` и не смотрит тесты. Он доказывает только наличие интерпретатора 3.13 на этой машине.
